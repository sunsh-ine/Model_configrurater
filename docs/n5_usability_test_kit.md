# N5 易用性验收测试包

**目的**：验证一个**不熟悉本项目源码**的人，只凭 README 与示例配置，能否完成
"改需求 → 跑评估 → 读懂结论 → 知道下一步还缺什么"。

> ⚠️ 这份验收必须由**真人**完成。Agent 自己跑脚本**不算**通过 ——
> 它已经知道答案，无法代表新使用者的理解成本。

---

## 1. 参与者要求

* 会用命令行（`cd`、`bash`、编辑 YAML），但**没有**读过本仓库源码；
* 事先**不要**看 `docs/` 下的内部报告与阶段文档，只看 `README.md` 与下面的任务单；
* 计时，遇到卡住就记下来，不要问 Agent"应该是什么"。

## 2. 环境准备（约 5 分钟）

```bash
# 仓库地址与目录名按实际填写（仓库根目录**就是**本项目，没有子目录）
git clone https://github.com/sunsh-ine/Model_configrurater.git
cd Model_configrurater

python3 -m venv .venv
.venv/bin/pip install -r requirements.lock
bash scripts/run_demo.sh /tmp/n5-demo      # 无 GPU、无网络即可
```

预期：命令最后打印 `报告: /tmp/n5-demo/demo_report.md`，且该文件与
`demo_result.json` 都已生成。若这一步失败，请先记录报错内容再继续（这本身就是一条反馈）。

## 3. 六个任务（按顺序做，记录每步耗时与卡点）

| # | 任务 | 考察点 |
|---|---|---|
| 1 | 打开 `data/examples/demo_qwen3_32b_h100.yaml`，把**并发**改成 64、把 **TTFT P99** 阈值改成 200ms | 能否找到并改对字段 |
| 2 | 重新生成报告（自己找命令：`README` 里有） | 能否不需要问人就能跑 |
| 3 | 回答：系统给出的**资源可行**部署配置是哪几个？哪几个静态不可行？ | 能否读懂候选表 |
| 4 | 在报告里指出：四类数字（**公开实测参考** / **模拟预测** / **假设成本** / **目标配置的真实实测**）各自**当前是否存在**；不存在的直接回答"不存在" | 四类证据能否分清，且能否承认"没有" |
| 5 | 回答：报告为什么说 SLA"证据不足"？若要拿到达标结论，下一步要做什么？ | 能否看懂缺口与下一步 |
| 6 | （可选）用 `scenario_simulation_auto.example.yaml` 跑一次模拟选型；若没装工具，报告怎么说明？ | 可选能力的可理解性 |

> **任务 4 的预期答案（判卷基准，别给参与者看）**：
> 默认 Demo 下 —— 公开实测参考 **存在**（第 2.1 节，14 条）；
> 模拟预测 **不存在**（未启用）；假设成本 **存在**（示例成本目录，不是报价）；
> 目标配置的真实实测 **不存在**，所以 SLA 结论是"证据不足"。
> 参与者回答某几类"不存在"是**正确**的。

## 5. 判定标准

* **通过**：任务 3、4、5 全部正确，且无需询问即可完成任务 2；
* **有条件通过**：任务 4 或 5 有误解，但错误集中在**措辞**而非结论；
  （注意：任务 4 答"模拟/实测当前不存在"是**正确**的，不算误解）
* **不通过**：把模拟预测当成实测、把假设成本当成报价、或找不到下一步建议。

只修**真实发现**的使用障碍（措辞、排序、缺失的说明）。
在有人实际卡住之前，**不**开发 Web 前端。
