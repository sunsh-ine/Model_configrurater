# AF5：真实 GPU 验证条件化门禁

基线：`030b65f`（AF 阶段尚未执行真机验证）

> 当前没有任何已授权的真实 GPU 测试窗口。AISimulate 的结果是**性能模拟**，
> 不是实测；在本文件列出的门禁全部满足并被明确授权前，不得启动真机 Benchmark，
> 也不得把任何 `predicted_*` 升级成 `observed_*`。

## 1. 执行前置条件（缺一不可）

| 条件 | 必须留下的证据 | 不满足时 |
|---|---|---|
| 明确授权 | 授权人、时间窗口、目标机器、允许占用的 GPU | 不执行 |
| 资源边界 | GPU SKU/卡数、是否独占、与现有服务的隔离方式 | 不执行；不得抢占 gunicorn/yolo-demo 等现有负载 |
| 环境身份 | 驱动/CUDA、框架与版本、模型 revision、权重精度、KV 精度 | 记录 unknown，不执行或只作探索性运行 |
| 负载身份 | ISL/OSL、到达模式、并发或到达率、数据集/轨迹、seed | 缺任一项则该次运行不进入校准 |
| 原始产物 | 客户端与服务端日志、逐请求记录、benchmark 配置、SHA256 | 缺哈希的产物不得作为证据 |
| 生产隔离 | 明确不是生产流量、不影响对外服务 | 不执行 |

## 2. 执行步骤

1. 冻结目标工作点：模型、硬件、TP/DP/PP、ISL/OSL、到达模式与并发/到达率；
   这些字段在运行前后不得改动。
2. 预热并记录预热请求数；预热不计入统计窗口。
3. 用声明的客户端工具采集逐请求 TTFT/TPOT/E2E 与终止状态，同时保留服务端日志。
4. 每个工作点至少重复 5 次（不同 seed 或不同时间窗），分别归档，不合并逐请求分布。
5. 对每个归档计算原始文件 SHA256，写入 manifest；记录采集时间与操作人。
6. 只有满足以下全部条件，才允许调用校准契约计算误差：
   - 身份字段两侧完全一致；
   - 原始文件存在且实际哈希与声明一致；
   - 指标口径与标准字典一致（`ttft_p99_ms`、`tpot_p99_ms`、
     `output_throughput_tok_s`）；
   - 实测值非空且非 0。
7. 重复性按运行级统计：报告 `通过数/运行数`；不得把多次运行的 P99 取平均后
   当作池化 P99。

## 3. 验收口径

* **工程通过**：产物齐全、哈希可复核、身份/口径完整、失败运行有隔离记录。
* **重复性结论**：只有全部运行达标才可写“稳定达标”；部分通过必须写
  `mixed` 并给出通过数；全部失败写未达标。
* **校准可用**：仅当第 2 节第 6 条全部满足；否则误差保持 unknown。
* **不可升级**：模拟预测、单 seed 结果、缺原始哈希的记录都不能升级为实测证据。

## 4. 禁止事项

* 不得用 AISimulate、扫描器均值或历史归档冒充目标配置实测；
* 不得跨 GPU/TP/DP/精度/负载身份复用 P99；
* 不得在缺字段时用 0、默认并发或默认到达率补齐；
* 不得在未授权的共享 GPU 上启动会干扰现有服务的压测；
* 不得把有限窗口的稳定性观察写成“长期稳定容量”。
